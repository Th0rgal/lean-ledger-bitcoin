# BOLOS Firmware Benchmark: `lean-ledger-bitcoin` vs Unmodified `LedgerHQ/app-bitcoin`

Reproducible head-to-head storage, RAM, worst-case call-graph stack, ARM Thumb instruction count, x86_64 `rdtscp` cycle count, host C unit-test suite, and live Speculos APDU latency comparison between:

1. **Reference (`LedgerHQ/app-bitcoin` unmodified)**: pinned upstream commit `f010982d3050e02813cd7129bebd68cf2d1f2099` (`APPVERSION 2.6.0`).
2. **Lean Optimized (`lean-ledger-bitcoin` BOLOS app)**: `LedgerHQ/app-bitcoin` `f010982` + `ffi/bolos/patches/app-bitcoin-lean-opt.patch`, linking freestanding LLVM IR kernels emitted from `BitcoinLedger/FreestandingKernels.lean` by `turbo-lean` (`feat/ledger-32bit-llvm-opt` @ `6eea5eaddb445b243cc45c13cb4096c87a251430`).
3. **Lean Same-Flags Control (`LLB_KEEP_UPSTREAM_DEFINES=1`)**: apples-to-apples control preserving every upstream `DEFINES` token (including `HAVE_SNPRINTF_FORMAT_LL`), isolating pure Lean kernel replacement + `qsort` elimination + bounded buffer right-sizing.

All raw measurements are generated by `benchmarks/bolos_benchmark.sh` and recorded in `benchmarks/bolos_results.json`.

### 2.3 Key Engineering Drivers of Flash Reduction
1. **Direct LTO Bitcode Emission (`turbo-lean` `feat/ledger-32bit-llvm-opt` + `scripts/build-freestanding.sh`)**:
   - Upgraded `turbo-lean` (`6eea5eaddb445b243cc45c13cb4096c87a251430`) to emit `-ffunction-sections -fdata-sections`, `optsize` attributes, and pure 32-bit partial-product 64-bit multiplication on `thumbv6m` without `__aeabi_lmul` runtime calls.
   - Compiled freestanding Lean LLVM IR directly with BOLOS's exact ROPI/RWPI LTO flags (`-Oz -flto -fropi -frwpi`), eliminating static-archive PIC/ROPI veneer trampolines and allowing LLD to inline scalar checks (`llb_valid_amount`, `llb_sighash_type_valid`, `llb_taproot_sighash_valid`, `llb_bech32_final_constant`, `llb_segwit_program_valid`, `llb_witness_opcode_to_version`, `llb_wallet_name_char_ok`, `llb_merkle_advance_state`) directly into C callers.
2. **Constructively Verified Bit-Smeared `largestPow2LtU32` (`BitcoinLedger/FreestandingKernels.lean` & `Proofs/FreestandingKernels.lean`)**:
   - Replaced the 32-case recursive `msbIdxGo` cascade inside `llb_merkle_advance_state` with a 5-shift bit-smearing round-down (`v := v ||| (v >>> 1) ... (v >>> 16); (v >>> 1) + 1`), shrinking `llb_merkle_advance_state` from ~390 B to ~56 B while preserving a constructive equivalence proof (`largestPow2LtU32_eq`, `0 sorryAx`, `0 Classical.choice`).
3. **Division-Free Satoshi Formatting (`llb_sats_div_1e8` / `llb_sats_mod_1e8`)**:
   - Replaced `uint64_t / 100000000`, `uint64_t % 100000000`, `uint64_t / 10`, and two `snprintf` passes in `format_sats_amount` (`src/ui/display_utils.c`) with verified `2^90 / 10^8` reciprocal multiplication in 32-bit limbs. Because no source file in `app-bitcoin` uses `%ll*` format specifiers once `format_sats_amount` is Lean-backed, filtering `HAVE_SNPRINTF_FORMAT_LL` drops unused 64-bit printf division (`__aeabi_uldivmod` + `__udivmoddi4`) cleanly (`-952 B` `.text`). Even with `LLB_KEEP_UPSTREAM_DEFINES=1`, our Lean build is `-1,024 B` smaller on Nano S+ and `-512 B` smaller on Nano X.
4. **Replacing Recursive `libc` `qsort` in BIP-327 MuSig2 KeySort (`src/musig/musig.h`, `src/handler/lib/policy.c`, `src/handler/sign_psbt/musig_signing.c`)**:
   - Replaced all 5 `qsort` call sites on small bounded MuSig2 key/index arrays (`MAX_PUBKEYS_PER_MUSIG`) with compact, deterministic, zero-recursion insertion sorts (`musig_sort_plain_pk`, `musig_sort_u16`), garbage-collecting `1,180 B` of `newlib` `qsort` + indirect comparator veneers.
5. **`.rodata` String & Table Compaction (`-124 B`)**:
   - Placed `segwit_addr.c` `charset[33]` as a `const char[]` in `.rodata` (eliminating ROPI pointer relocation), deduplicated `SIGHASH_*` string/validation logic via `llb_sighash_type_valid` / `llb_taproot_sighash_valid`, and unified `register_wallet` / `sign_message` / `get_extended_pubkey` validation through `llb_wallet_name_char_ok` and `llb_bip32_pubkey_export_prefix_ok`.

- **Stack Safety**:
  - Worst-case static call-graph stack remains at `12,496 B < 16,384 B` on Nano S+ and `11,248 B < 12,288 B` on Nano X, while **eliminating recursive `qsort`** from the call graph (`has_recursive_qsort: true -> false`).

  - `format_sats_amount` call-chain stack drops by **`-196 B`** on Nano S+ (`268 -> 72 B`) and **`-172 B`** on Nano X (`268 -> 96 B`) by avoiding `snprintf` stack frames.
  - Every standalone freestanding Lean kernel archive passes `./scripts/build-freestanding.sh`'s `.su` audit (`thumbv8m.main` worst frame `56 B`, `thumbv6m` worst frame `72 B`, `riscv32imac` worst frame `16 B`, `x86_64` worst frame `0 B`).
